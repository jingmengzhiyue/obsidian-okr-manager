# Vault OKR Manager 1.4.1 — Safer saves and reliable rollover

This patch improves data preservation, concurrent editing, and period rollover.

**Requires Obsidian 1.7.2 or later.** No file-format version change or new production dependency is introduced.

## Fixed

- Preserve custom YAML properties, tags, and KR extension fields when saving Objectives.
- Read check-ins using `-`, `*`, or `+` list markers. Reject writes when managed records are malformed, contain conflicting duplicates or invalid numbers, or cannot be safely migrated, leaving the original file intact. Identical duplicates can be consolidated.
- Preserve independent changes saved from other plugin dialogs when editing Objectives, KRs, deadlines, and reviews. Conflicting field edits are rejected with guidance to copy unsaved content and reopen the dialog; target, unit, and current value are checked together.
- Save literal characters such as `$&` and `$$` in review text without altering them, and preserve historical snapshots when editing review narratives.
- Keep rollover checkbox state consistent after returning from the retrospective editor.
- Determine incomplete KRs from actual values in automatic progress mode, so a rounded display such as `199/200 → 100%` does not exclude unfinished work. Manual mode continues to use saved progress.
- Allow remaining and newly added KRs to roll over after reopening a partially rolled period, while preserving existing rollover mappings.
- Avoid reusing IDs referenced by rollover history or review snapshots when creating Objectives, KRs, or applying templates.
- Preserve the latest progress and blocker state when adding a backdated check-in. Recalculate deltas by check-in date, using save order for entries on the same day.
- Clear affected caches after failed rollover or template creation is rolled back, so retries do not use deleted Objectives.

## Compatibility and upgrade

- Minimum Obsidian version remains **1.7.2**.
- No manual file-format migration is required when upgrading from 1.4.0.
- If a save reports malformed records, open the file named in the error and repair the format or conflicting content before retrying.
- Edit-conflict protection applies to saves made through this plugin; it does not replace your sync provider's file-conflict handling.

## Installation

If installed through Obsidian's community plugin directory, use **Settings → Community plugins → Check for updates** when this version is available.

For manual installation or update, download **main.js**, **manifest.json**, and **styles.css** from this release and place all three files in:

```text
<vault>/.obsidian/plugins/vault-okr-manager/
```

Reload Obsidian after replacing the files, and enable the plugin if needed. The automatically generated **Source code** archives are not installable plugin builds.

## Verification

All **113 automated tests** pass, along with ESLint, TypeScript checking, the production build, and Git whitespace validation. Tests cover persistence, dialog submission, edit conflicts, historical check-ins, partial rollover, historical ID references, and rollback behavior using an in-memory Vault.

Real-device end-to-end testing in Obsidian desktop, mobile, and third-party sync services has not been performed for this patch.

## 中文更新说明

1.4.1 重点修复保存、编辑冲突和周期结转问题。

- **更安全地保存数据**：保留自定义 YAML 属性、标签和 KR 扩展字段；兼容多种 Markdown 列表标记。遇到损坏记录、冲突的重复记录或非法数值时拒绝写入，保留原文件。
- **防止多窗口编辑覆盖**：保留其他插件窗口已保存的独立修改；字段冲突时提示复制未保存内容并重新打开窗口。目标值、单位和当前值会一起检查。
- **保留复盘原文与历史快照**：正确保存 `$&`、`$$` 等字符，编辑正文不会重建历史快照。
- **修复周期结转**：从复盘窗口返回后复选框状态保持一致；自动进度模式按实际数值判断完成情况，避免 `199/200` 四舍五入为 `100%` 后被遗漏。部分结转后重新打开周期，剩余和新增 KR 仍可继续结转。
- **保护历史关联**：创建目标、KR 或应用模板时，避开历史结转和复盘快照引用的 ID，避免删除后复用造成错误关联。
- **正确处理补录与失败重试**：补录历史打卡保留最新进度和阻碍状态，并按业务日期重算增量；结转或模板创建失败回滚后清理缓存。

**升级与兼容性**：最低要求仍为 Obsidian **1.7.2**。从 1.4.0 升级无需手动迁移文件格式，无新增生产依赖。如提示记录无法解析，请修复提示文件中的格式或冲突内容后重试。插件内编辑冲突保护不能替代同步工具的文件冲突处理。

**手动安装**：下载本次 Release 的 `main.js`、`manifest.json`、`styles.css`，放入仓库的 `.obsidian/plugins/vault-okr-manager/`，然后重新加载 Obsidian。请勿使用自动生成的源码压缩包作为插件安装包。

**验证范围**：113 项自动化测试、ESLint、TypeScript 类型检查、生产构建和差异格式检查通过；尚未完成真实 Obsidian 桌面端、移动端及第三方同步服务的端到端验证。
